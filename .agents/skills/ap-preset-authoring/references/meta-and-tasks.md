# 元指令、生成来源与历史改写

本文说明 AP 在每次生成开始时如何**分类**这一轮（元指令、正则标记、内置任务、生成来源），如何**选择工作流**，以及发送前如何**改写聊天历史**（剔除元指令、省 token）。清单字段见 [manifest.md](manifest.md) 的 `meta`、`regex`、`tokenSaving` 部分。

## 元指令

元指令是用户写给叙述者本人的话，以触发词（`meta.trigger`，默认 `@{{ap::name::<narrator>}}`，如 `@Freesia`）开头。

**识别规则**：

- 触发词先做 `{{ap::name::…}}` 与 ST 宏展开，然后**大小写不敏感**地查找；
- 触发词后紧跟字母、数字或下划线时不算（`@Freesiax` 不是触发）；
- **段落写法**：从触发词到下一个空行（`\n\s*\n`）或输入结尾。开头的空白、`,` `，` `:` `：` 去掉；
- **花括号写法**（`meta.wrap: true` 时）：`@Freesia{ … }`，花括号可嵌套，可跨段落；
- 一条输入里可以有多段元指令。

用户可在面板配置页「元指令」区块关闭元指令（配置 `meta.enabled`，默认 `true`）。关闭后输入一律按普通输入处理：不识别触发词（`meta.present` 恒为假、不产生纯元指令或混合轮次、不检查 `meta.tasks`），历史中较早用户消息里的元指令文字原样发送，`{{ap::recent_meta}}` 为空，ST 的代写按钮也不再被拦截、按原生代写执行。已有的纯元指令轮次仍按下文从历史中剔除。

去掉所有元指令片段后：

| 剩余内容 | 分类 | 条件变量 |
| --- | --- | --- |
| 没有元指令 | 普通输入 | `meta.present == false` |
| 空 | **纯元指令** | `meta.present && meta.pure` |
| 非空 | **混合** | `meta.present && meta.mixed` |

元指令文字可用 `{{ap::input::meta}}`（各段以空行连接）读取；`{{ap::recent_meta}}` 输出最近 `meta.recentCount` 次元指令及叙述者的回复（见 [macros.md](macros.md)），条件变量 `meta.recent` 表示它非空。

## 正则标记

`regex` 中的每条规则在分类时求值，结果写入 `flags.<id>`：

- `target: input`（整条输入）、`meta`（元指令片段，以空行连接）或 `recent:<N>`（最近 N 条消息，最多取到最近 6 条）；
- 匹配并且 `requires` 条件成立时为真。`requires` 求值时只能使用 `meta.*` 与 `flags.*`（前面规则的结果）。

## 内置任务

**只在纯元指令时**检查 `meta.tasks`，先 `summary` 后 `impersonate`，第一个成立的条件决定 `meta.task`：

```yaml
regex:
  - { id: summary, pattern: "总结|summar", target: meta }
  - { id: impersonate, pattern: "代写|write my", target: meta }
meta:
  tasks: { summary: flags.summary, impersonate: flags.impersonate }
```

任务本身不改变流程，只是给模组一个条件（例如 `when: 'meta.task == "summary"'` 的模组请求 `recap` 结构）。点击 ST 的代写按钮时，AP 把 `meta.impersonatePrompt` 填入输入框并发送（输入框里已有的草稿换行附在后面），所以代写也是一次纯元指令。

## 生成来源

每次生成有一个**来源** `gen.origin`：

- `story`：拦截器参与（ST 原生 `Generate`）、生成类型为 `normal` `regenerate` `swipe` `continue` 之一，并且**不是**纯元指令；
- `task`：其他所有情况——纯元指令、后台生成（`quiet`）、ST 原生代写（`impersonate`）、脚本 / 其他扩展调用（`script`）。

脚本可以强制下一次生成的来源：

```js
AdvancedPreset.nextGeneration({ origin: 'story' }); // 只影响下一次生成
```

### 工作流选择

- `story`：配置 `connection.workflow` 指定的工作流；找不到时用第一个 `kind: story` 工作流；
- `task`：第一个 `kind: task` 工作流（或 id 为 `task` 的工作流）。

**继续**（`continue`）与 ST 原生**代写**（`impersonate`）是“直通”生成：区域照常组装，但不运行工作流、不接管请求，由 ST 原样发送。

## 轮次类型

生成结束后，sidecar 的 `turn` 记录这一轮的类型：

| `turn` | 条件 |
| --- | --- |
| `story` | 故事轮（含纯元指令但模型仍写了正文的情况） |
| `meta-mixed` | 混合元指令的故事轮 |
| `meta-pure` | 任务轮、没有正文、不是总结 / 代写 |
| `summary` | 任务轮、没有正文、`meta.task == "summary"` |
| `impersonate` | 任务轮、没有正文、`meta.task == "impersonate"` |

后三种是**纯轮次**：消息正文 `mes` 为回复的纯文本（没有回复时，代写 / 总结轮为 `…`）。

## 历史改写

拦截器在 ST 组装提示词之前改写**历史副本**（真实聊天不变）：

1. **剔除纯轮次**：`turn` 为 `meta-pure` / `summary` / `impersonate` 的助手消息，连同触发它的用户消息一起不发送（当前输入除外）；
2. **剥离元指令**：较早用户消息中的元指令片段被去掉；剥离后为空的用户消息不发送；当前输入保持原样；
3. **省 token**（启用时，见下）；
4. **附带事件摘要**：`synopsis` 结构声明了 `history: N` 且请求它的模组已开启时，最近 N 条助手消息（含已被省 token 替换的）中仍为原文的，按 `historyTemplate` 附上自己的事件摘要（见 [structures.md](structures.md#synopsis)）；
5. **批注回传**：有 `annotations` 结构且请求它的模组已开启时，最近几条仍为原文的助手消息带上自己的行内批注（CriticMarkup）。

开启缓存优化后，第 3–5 步的结果对较早的消息是“粘性”的，见 [缓存优化](#缓存优化粘性渲染)。

## 省 token

配置 `tokenSaving.enabled` 为真时（默认关闭），从末尾开始数助手消息：

- 最近 `keepFullTurns` 条助手消息以及它们前面的用户消息保持完整（用户消息与其后的助手回复算同一轮）；当前输入总是保留；
- 更早的消息中：
  - 已被总结覆盖的（真实索引 ≤ 当前总结的 `coversUpTo`）**不发送**，由模组通过 `{{ap::recap}}` 提供总结；
  - 用户消息按 `userInput` 处理：`keep` 原样发送；`truncate` 超过 `truncateUserAfter` 个字符时截断并加 `…`（0 表示不截断）；`remove` 不发送。扩写类写法中正文（及其事件摘要）已包含用户输入，适合 `remove`；
  - 助手消息如果有事件摘要（`synopsis` 结构），替换为 `tokenSaving.synopsisTemplate` 渲染的一行（占位符 `{{time}}` `{{location}}` `{{event}}` `{{summary}}`）；没有则保持原样。

`keepFullTurns`、`truncateUserAfter`、`userInput` 的默认值来自清单 `tokenSaving`，可被配置覆盖。条件变量 `features.tokenSaving` 表示已开启，`recap.present` 表示有生效的总结。

## 缓存优化（粘性渲染）

省 token、附带摘要和批注回传都是**滑动窗口**：每一轮都有某条较早的消息换了渲染方式（原文变成摘要、摘要附件或批注被去掉），提示词前缀在那里改变，服务商的提示词缓存从那里开始失效。

配置 `cache.enabled` 为真时（默认关闭），在缓存可能仍然命中的时候，每条历史消息**沿用上一次请求的渲染方式**——原文 / 摘要 / 截断 / 不发送、是否附带摘要、是否附带批注；只有新消息按当前规则渲染。以下任一情况发生时，所有消息一次性按当前规则渲染（**刷新**）：

| 原因 | 条件 |
| --- | --- |
| `first` | 这个聊天没有上一次请求的记录 |
| `ttl` | 距离上一次**成功**请求超过 `ttlMinutes` 分钟（0 表示不限） |
| `model` | 聊天来源、模型或自定义地址改变 |
| `tools` | 传输方式、工具 / Schema、强制调用、并行工具或示范轮次改变 |
| `prompt` | 历史之前的提示词改变（世界书、插在历史前的关键词模组、系统提示词……） |
| `turns` | 推迟变更的连续请求数超过 `maxDeferredTurns`（0 表示从不推迟） |

细节：

- 沿用的渲染一直保持到**第一处无法避免的差异**——新消息、编辑过的消息、删除的消息、ST 的深度注入等。缓存从那里本来就会失效，所以之后的消息直接使用当前规则，不计入推迟；
- 只有某条消息因此保留了旧渲染（与当前规则不同）时才算“推迟”；连续推迟的请求数超过上限时刷新；历史与上一次请求完全相同的请求（重新生成、滑动生成新版本、重试）不算新的一轮；
- 被总结覆盖的消息、纯轮次、元指令剥离不受影响，总是按当前规则处理；
- 状态按聊天保存在浏览器本地（见 [artifact-and-runtime.md](artifact-and-runtime.md#缓存状态)），在请求**成功**（或中止但已有输出）后写入；失败的请求不改变状态；
- 只有故事轮会写入渲染方式；任务轮（总结、代写、记忆整理……）使用同样的沿用规则，命中时只刷新时间；dry run 不写入；
- 调试页“最近组装”显示本次是沿用还是刷新（及原因）、沿用 / 新渲染 / 推迟的条数；请求列表显示服务商返回的缓存命中 token 数。

实现：拦截器把每条历史消息按两种方式渲染，交给 ST 的是沿用版本并带一个不可见标记（私用区字符，不会触发世界书关键词）；提示词就绪后 AP 依据标记找到这些消息，决定从哪里开始换成当前规则，并去掉标记。脚本路径的回填同样处理。

## 用户输入整形

预设声明了 [`inputShaping`](manifest.md#用户输入整形-inputshaping) 时，AP 对本次输入做整形：

1. **判断**：拦截器改写历史之后，如果历史副本以用户消息结尾（`continue` 没有输入），就给这条消息加一个不可见标记（私用区字符，与缓存优化的标记不同），并记下它送出的文字；
2. **定位**：提示词就绪后，在 `historyStart` 与 `historyEnd` 锚点之间找带标记的消息（缺少锚点时在全部消息中找）。找到、并且标记前的文字以记下的文字结尾时，整形生效——ST 在它之后插入的深度注入、作者注释、`quiet` 提示词都不影响；ST 加的名字前缀被识别并保留（`wrap`）或一并去掉（`extract`）；
3. **组装**：条件变量 `input.shaped` 为真，`{{ap::input::text}}` 在区域中先留一个占位符；
4. **缓存优化**之后：`wrap` 把这条消息中的输入换成展开后的模板；`extract` 把输入从消息中去掉，消息只剩名字前缀或空白时整条删除（图片等附件保留在原消息中）；所有占位符换成输入原文；
5. 所有标记被去掉，不会发给模型。

不整形的情况：预设没有声明；历史以助手消息结尾（`continue`、`/trigger`、其他扩展在助手消息后发起的生成）；脚本路径中脚本在聊天之后又加了用户消息；`dryRun`（ST 的 token 计数）；找不到带标记的消息（被其他扩展改写，警告 `input shaping: …`，原样发送）；`extract` 模式下提示词里没有 `{{ap::input::text}}`（放它的区域没有锚点或被禁用，警告 `input shaping: …`，输入留在历史中，绝不丢失）。

脚本路径的回填同样处理：真实聊天以用户消息结尾、这条消息与历史中的某条对齐、且它之后没有其他用户消息时整形。

预填充传输下整形先于预填充整形：`wrap` 后的文字按 `historyItemTemplate` 带上用户前缀；`extract` 后由放回输入的区域决定它出现的位置。

调试页“最近组装”用一个标签显示本次输入是否整形（`输入已包裹` / `输入已提取` / `输入未整形`）。

## 脚本路径的回填

脚本 / 其他扩展直接调用生成时拦截器不会运行。AP 在提示词就绪后尝试**回填**：取 `historyStart` 与 `historyEnd` 锚点之间的用户 / 助手消息，与真实聊天从末尾对齐（忽略宏与空白；相等、包含或 Dice 系数 ≥ 0.9 视为匹配，允许跳过少量插入的消息），然后对匹配到的消息执行同样的历史改写。

匹配率低于 90% 或缺少语义锚点时，历史保持原样，并在调试信息中给出警告（`backfill: …`）。回填也会标记本次输入，见[用户输入整形](#用户输入整形)。脚本发起的任务生成不请求结构（见 [structures.md](structures.md#何时请求结构)）。
